# Atlas lead-intake boundary

The browser TUI distributes a configured callback number through selected logged-in real-estate portals. Confirmed interest submissions are the primary result. Authenticated contact details revealed afterward are a supplementary source, with listing provenance and identity review. Viewing bookings and seller-chat messages have separate result types.

The self-hosted Baileys router and conversational agent remain the other developer's service. Follow the existing contract in `baileys-router/README.md`. The TUI's reviewed introduction names Atlas and asks for the appropriate sales/operations/software decision-maker or a willing manager referral. Do not infer that a portal relay number identifies a direct seller or is available on WhatsApp.

Qualification should retain only facts supplied by the contact: company name, role, team size when volunteered, relevant need, referral permission, official manager contact, next action and follow-up date. Unknown fields remain unknown. A sent message does not establish a response, referral or Atlas sales opportunity. Respect opt-outs and preserve the existing durable send IDs; do not repeat an uncertain send automatically.

Operational checks before live use: the chosen callback number must be reachable, portal accounts must use the intended number where the website relies on its registered identity, the WhatsApp sender must be the configured burner/session, and the external router must implement the health/session/message/event contract. No external agent or CRM deployment is claimed by the TUI build.
